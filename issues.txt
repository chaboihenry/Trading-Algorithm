--------------------------------------------------------------------------
[ML-1] CRITICAL | OPEN | Frequency mismatch — whole file is intraday
  Built on microstructure machinery: Dollar Imbalance Bars at $50M
  threshold (AFML Ch 2), 1-min resampling, z-score over 50 DIBs in
  event-time. The strategy now trades DAILY cointegrated spreads with
  day-scale half-lives (DUK basket ~87d; HYG/TLT only passes at 252d
  window). Per AFML Ch 3, the meta-model must train on the SAME primary
  signals the live bot generates. Training on 1-min z-crossings while the
  bot fires on daily z-crossings means the learned P(profit) is calibrated
  to a strategy we are not running.
  FIX: full rebuild at daily frequency. Drop DIB engine + 1-min resample.
  Keep frac-diff (Ch 5), triple-barrier (Ch 3), purged K-fold CV (Ch 7),
  fed with daily inputs. Define the daily primary signal FIRST (z-window,
  threshold, vertical-barrier horizon relative to each basket half-life);
  labels flow from that.

[ML-2] HIGH | OPEN | Hardcoded "2024_01" cutoff (appears twice)
  construct_m1_dibs and the price-load loop both filter f >= "2024_01.parquet",
  using 2024+ only and discarding 2021-2023. Inconsistent with the
  252-day / 5-year windows cluster_discovery uses.
  FIX: parameterize the lookback; align with the window the primary model
  is validated on.

[ML-3] MEDIUM | OPEN | scale_pos_weight may be inverted

[PA-1] HIGH | OPEN | pct_change() on spread level is wrong return def
  spread_returns = spread_val.pct_change(). Spread is a signed mean-
  reverting series (mixed-sign cointegration weights) oscillating around an
  arbitrary constant that can be near zero or cross zero -> pct_change
  explodes (e.g. +0.01 to +0.5 = +4900%) and is meaningless even when
  positive. HRP's cov/corr matrices are then built on distorted numbers,
  so capital allocation is computed on noise.
  FIX: use spread_val.diff() (daily PnL per unit position) normalized by
  gross notional sum(|w_i|*P_i), or standardize returns before HRP.

[PA-2] MEDIUM | OPEN | HRP degenerate with too few baskets
  HRP's value is taming ill-conditioned cov across MANY assets. With 0-1
  surviving baskets, clustering is meaningless (equal-weight fallback only
  triggers for <2). If universe yields few baskets, prefer honest equal-
  weight over HRP theater.

[PA-3] LOW | OPEN | cap/floor feasibility unchecked
  50-iteration cap+floor loop has no feasibility check (needs N*floor <= 1
  <= N*cap). If infeasible it exits unconverged, then renormalizes,
  silently violating cap/floor.
